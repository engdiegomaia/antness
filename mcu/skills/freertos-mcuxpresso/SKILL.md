# FreeRTOS + NXP MCUXpresso SDK

## Orient first

```
FreeRTOSConfig.h            -> tick rate, heap scheme, priorities, assert config
board/                      -> board.c, clock_config.c, pin_mux.c, peripherals.c
devices/<part>/             -> CMSIS headers, startup, linker scripts
components/ drivers/        -> SDK fsl_* drivers
```

Identify the exact part (`MIMXRT1062DVL6A`, `LPC55S69`, `MKE18F`) — the SDK is
part-specific and errata differ across silicon revisions.

## FreeRTOSConfig.h — what to check every time

```c
#define configTICK_RATE_HZ              1000
#define configMAX_PRIORITIES            8
#define configSUPPORT_STATIC_ALLOCATION 1   /* prefer static */
#define configSUPPORT_DYNAMIC_ALLOCATION 0  /* off if you can */
#define configCHECK_FOR_STACK_OVERFLOW  2   /* always on in dev */
#define configUSE_MALLOC_FAILED_HOOK    1
#define configASSERT(x)  if(!(x)) { taskDISABLE_INTERRUPTS(); for(;;); }
#define configMAX_SYSCALL_INTERRUPT_PRIORITY  (2 << (8 - configPRIO_BITS))
```

`configMAX_SYSCALL_INTERRUPT_PRIORITY` is the critical one: **any ISR at a higher
priority (numerically lower) must never call a `FromISR` API.** Getting this wrong
produces corruption that appears hours later.

On Cortex-M with NVIC, also call `NVIC_SetPriorityGrouping(0)` — FreeRTOS requires all
bits as preempt priority.

## Task design

```c
/* Static allocation — deterministic, no heap */
static StackType_t  task_stack[TASK_STACK_WORDS];
static StaticTask_t task_tcb;

xTaskCreateStatic(task_fn, "sensor", TASK_STACK_WORDS, NULL,
                  TASK_PRIO_SENSOR, task_stack, &task_tcb);
```

- Stack size is in **words**, not bytes. A frequent off-by-4 source.
- One responsibility per task. A task that polls three peripherals is three tasks or
  an event-driven one.
- Never `vTaskDelay` inside a critical section or with a mutex held.
- `vTaskDelayUntil` for periodic work — `vTaskDelay` drifts.

## ISR interaction

```c
void UART_IRQHandler(void) {
    BaseType_t higher = pdFALSE;
    uint8_t byte = UART->DATA;
    xQueueSendFromISR(rx_queue, &byte, &higher);
    portYIELD_FROM_ISR(higher);          /* mandatory, not optional */
}
```

Omitting `portYIELD_FROM_ISR` produces latency that varies with tick rate — a classic
"works in debug, fails in release" bug.

## SDK driver usage

```c
/* Every fsl_* driver follows: GetDefaultConfig -> modify -> Init -> use -> Deinit */
lpuart_config_t cfg;
LPUART_GetDefaultConfig(&cfg);           /* never skip: fields you do not set are garbage */
cfg.baudRate_Bps = 115200;
cfg.enableTx = true;
LPUART_Init(LPUART1, &cfg, CLOCK_GetFreq(kCLOCK_OscClk));
```

- Check the return `status_t` of every `*_Init`, `*_Transfer*`, `*_Write*`.
- Use the `_RTOS` driver variants (`LPUART_RTOS_Init`, `SPI_RTOS_Transfer`) when
  calling from tasks — they handle blocking correctly with FreeRTOS.
- `clock_config.c` and `pin_mux.c` are generated by the MCUXpresso Config Tools. Edit
  the tool project (`.mex`) and regenerate; hand edits are lost.

## i.MX RT specifics

- Code runs from external QSPI flash via FlexSPI by default — XIP. Latency-critical
  code and ISRs go in ITCM: `AT_QUICKACCESS_SECTION_CODE()` / `__RAMFUNC`.
- Data cache is on: DMA buffers must be cache-line (32 B) aligned and maintained with
  `SCB_CleanDCache_by_Addr` / `SCB_InvalidateDCache_by_Addr`, or placed in a
  non-cacheable MPU region (`AT_NONCACHEABLE_SECTION_ALIGN`).
- The MPU configuration in `BOARD_ConfigMPU()` is not optional — wrong attributes on
  the SDRAM/OCRAM regions cause silent corruption.
- DCD / boot header configuration (`dcd.c`, `evkbimxrt1050_flexspi_nor_config.c`) is
  part of the boot chain. Changes there risk an unbootable board — apply
  `shared/rules/10-hardware-safety.md`.

## Debugging

- `configCHECK_FOR_STACK_OVERFLOW 2` + `vApplicationStackOverflowHook`
- `uxTaskGetStackHighWaterMark()` logged periodically during soak
- FreeRTOS-aware debugging in MCUXpresso IDE / Ozone / SEGGER SystemView for trace
- Hard fault: decode CFSR/HFSR/MMFAR/BFAR, see `skills/mcu-debug-trace`

## Never

- Call a non-`FromISR` API from an ISR.
- Use `heap_3` (malloc wrapper) in a product — prefer `heap_4` or static-only.
- Share a bus (I2C/SPI) between tasks without a mutex around the whole transaction.
- Leave `PRINTF` (blocking, polled UART) in a time-critical path.
